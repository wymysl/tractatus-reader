## App changes

Fixed a rendering bug in how statement text reaches the page, surfaced
directly by today's thesis: the source data marks optional print
hyphenation points with a literal `\-` (TeX's discretionary hyphen —
`atom\-ic`, meaning "break here if the typeset line needs it, otherwise
run the letters together"). `site/app.js` writes `st.en`/`st.de` straight
into `innerHTML`; nothing ever did the line-breaking that would make `\-`
meaningful, so it has rendered as a literal backslash-hyphen in the
statement text on the live site. 2.11's own English carries three
instances in one clause, `non-ex\-is\-tence` — highly visible, since the
statement block is the largest, most prominent text on the page, and
today's explanation opens by treating this exact clause as a precisely
chosen piece of text.

Surveyed the full data file before fixing: 38 entries across chapters
2 through 6 carry the same `\-` marker (in `en`, `de`, or both), three of
them already published — day 28 (2.0231, German), day 30 (2.0233, German
and English), day 45 (2.05, English). All three have been rendering
broken text since publication.

Fix, in `build.mjs`: a new `stripSoftHyphens` function strips `\-`
sequences from every statement's `de` and `en` at load time, before the
cleaned data reaches `tree.json` or any `units/day-NNN.json`. One
correction point covers both consumers that read those fields
(`site/app.js`'s statement block and its tree view) rather than patching
each separately. `data/tractatus.json` is not touched — the guardrail
holds; only the generated output changes. Two new tests in
`tests/build.test.mjs`: a direct test of `stripSoftHyphens`, and an
end-to-end build test confirming a `\-` in fixture source data comes out
clean in both `dist/units/day-001.json` and `dist/tree.json`. `npm test`
(32 passing, up from 30) and `node build.mjs` both green before
committing.

This changes how already-published days render: days 28, 30, and 45 will
show correct, unbroken English (and, for 28 and 30, German) statement text
for the first time since they went live. No `content/` or `journal/` file
changes — only the build pipeline between the immutable source data and
the generated site. Flagged here per METHOD.md's confession rule for
revising the past, same as day 50's tree-depth fix one day prior.
