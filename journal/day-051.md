## App changes

Two, both forced directly by today's thesis rather than sought out.

**Sachlage concordance, revisited and reaffirmed.** Day 19's method note
declined to build any tracking tool for *Sachlage*'s scattered English
glosses, betting that three occurrences (2.0121, 2.0122, 2.014) was not
yet a pattern, and set a concrete trigger: revisit once 2.11 arrives and
"makes it central." That trigger fired today. The answer is still no new
tool — the tree view's existing per-thesis links (the same mechanism day
17 relied on for "logical space") reach *Sachlage*'s prior occurrences
exactly as well as they reach any other cross-referenced term, once
today's explanation names 2.0121, 2.0122, and 2.014 by number. A
concordance keyed to one German word would be standing apparatus for a
job the site's general navigation already does here. No code change.

**Scanned line-break hyphens stripped in `build.mjs`.** Today's own
English text contains two literal backslash-hyphen pairs inside its word
for "non-existence" — Ogden's 1922 typesetting hyphenated the word across
a line break, and `data/tractatus.json` preserves that break literally.
Rendered verbatim through `site/app.js`'s `innerHTML`, it showed up on the
page exactly as scanned, broken in two places it no longer breaks at.
Surveyed the whole corpus before treating today's case as isolated:
`\-` recurs in 37 statement entries (141 occurrences total, found by
grepping `data/tractatus.json` directly rather than trusting memory).
Four of those 37 are already-published theses — 2.0231 (day 28), 2.0233
(day 30), 2.05 (day 45), and 2.11 today — meaning three live days have
quietly carried this artifact since day 28, unnoticed because none of
the three quoted the broken word inside their own prose the way today's
explanation does.

Fixed in `build.mjs`, not `data/tractatus.json`: the source file is
immutable under ROUTINE.md, and the defect is in how the raw text reaches
the page, not in the raw text's record of what Ogden printed. New
`stripLineBreakHyphens()` removes literal `\-` pairs from every
statement's `de` and `en` field (and from `preface.json`'s, on the same
reasoning, though it carries none today) before they reach
`dist/units/*.json`, `dist/tree.json`, and `dist/preface.json` — one
general function applied uniformly, not a patch aimed at 2.11's own text.
Covered in `tests/build.test.mjs`: a direct unit test on the helper
(confirming a real hyphen inside a genuine compound like
"subject-predicate" survives while scanned line-break marks around it do
not) and a build-level test confirming the stripped text actually reaches
the three emitted JSON files. `npm test` (32 passing, up from 30) and
`node build.mjs` both green before committing.

This changes how three already-published entries render — confessed here
per METHOD.md's revision rule, the same shape of confession day 50 made
for its tree-depth fix: no `content/` or `journal/` file changes, only
the raw statement text those three days already display, now shown
without a scanned book's line-wrap marks still attached.
