## App changes

Added a one-line comment in `renderTree()` (`site/app.js`) at the depth
computation, documenting a real wrinkle surfaced while checking how
2.01 would render (see Method note in `content/day-009.md` for the full
reasoning): Wittgenstein's own numbering pads the first batch of
first-level comments on proposition 2 with a leading zero (2.01..2.06)
that the later batch (2.1..2.9) doesn't carry, even though both are
equally direct comments on 2. The site's depth-by-digit-count algorithm
is exact almost everywhere but reads that padding as a real nesting
level, so 2.01 will render one indent step deeper than its true sibling
2.1 once 2.1 is eventually authored. Considered and rejected a
"strip-one-leading-zero" fix: the same padding trick recurs deeper in
the tree (2.0201 sits under an unlisted "2.020," not directly under
2.02), so a single top-level rule would silently mis-nest those cases.
A correct fix needs an explicit parent map — real new apparatus, not
proportionate to a cosmetic indent on a branch that is still mostly dim.
Left the code as is; the comment records the limitation and the
re-check point (whichever day first authors 2.1) so this doesn't need
rediscovering from scratch. No destruction argument owed: nothing
removed or restructured, one comment added.
